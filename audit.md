# spec.md vs. code — Audit

Date: 2026-05-21
Scope: comparison between `spec.md` and the current implementation under `src/ingest_pipeline/` and `prompts/`.

This file lists material discrepancies discovered during a spec review. Each item is classified as **breaking** (the spec describes something a user/contributor would act on that no longer exists or differs in shape), **missing** (the spec omits a real feature), or **drift** (the spec is technically wrong about implemented behaviour).

---

## 1. CLI signatures wrong — **breaking**

`spec.md` § "CLI Entry Points" and § "Commands" show:

```
uv run ingest-add <source>
uv run ingest-amend <source>
```

The actual Click commands in `cli.py` require **two positional arguments**:

```
uv run ingest-add <source-subdir> <destination>
uv run ingest-amend <source-subdir> <destination>
```

Anyone copy-pasting from the spec gets a Click error.

## 2. Locale subsystem entirely absent — **missing**

The pipeline now has a full locale-detection and selection feature, none of which appears in the spec:

- `detect_locale()` in `extract.py` (stopword-frequency fr/en/und detector) — populates a `locale:` field in every extract front matter.
- `_resolve_locale()` in `pipeline.py` runs between summarize and reduce; it surveys every `_summary_*.md` and stores the result in `state.locale`.
- `confirm_locale()` in `ui.py` interactively prompts when multiple locales are detected.
- `--locale` flag on all three CLI commands (and the matching `.claude/commands/*.md`) forces a locale and skips detection.
- `locale:` field appears in the front matter of every extract, summary, and reduce file.
- `State` dataclass carries `locale: str = "und"`.

The spec needs a new "Locale" section and updated front-matter examples.

## 3. Front-matter schemas drifted — **drift**

| File type | Spec says | Code writes |
|-----------|-----------|-------------|
| Extract `.md` | `source, category, extracted_at, ingest_id` | adds `locale` (between `category` and `extracted_at`) |
| `_summary_*.md` | `source_summary, tags, summarized_at` | adds `type: summary` (first), adds `locale` |
| `_reduce_*.md` | `type, directory, sources, tags, reduced_at` | adds `locale` (between `directory` and `sources`) |
| `index.md` | (no front matter shown) | writes `type: index, generated_at` |

## 4. Summary prompt contract wrong — **drift**

`spec.md` § "Step 2 — Summary" shows:

```
Output format exactly:
---
source_summary: ...
tags: [tag1, tag2, ...]
summarized_at: ...
---

## Summary
{summary text}
```

The real `prompts/summarize.txt` instructs Claude to return **prose + `## Key Topics` bullet list**, with **no front matter** (the pipeline prepends it). Tags are parsed out of `## Key Topics` by `reduce._extract_tags()` — they are NOT produced inline by the model. There is also no `## Summary` heading in the actual output.

## 5. Reduce prompt contract wrong — **drift**

`spec.md` § "Step 3" shows a `## Directory Summary: {dir_name}` heading followed by a `## Contents` markdown table:

```
| File | Tags |
|------|------|
| [_summary_doc1.md](...) | tag1, tag2 |
```

Real `prompts/reduce.txt` produces **prose + `## Components` + `## Key Topics`** — no table, different headings. Front matter is again prepended by Python and not generated by the model.

## 6. Index prompt contract wrong — **drift**

`spec.md` § "Step 4" shows headings `# Knowledge Base Index`, `## Directory Overview`, `## Thematic Index`, `## Top-Level References`.

Real `prompts/index.txt` produces `## Overview`, `## Directory Structure`, `## Key Concepts`, `## Quick Reference`. Additionally, `index.py` appends a `## Non-Processed Documents` section listing oversized/skipped binaries — this is not mentioned anywhere in the spec.

## 7. File classification extension list incomplete — **missing**

`spec.md` § "File Classification" lists 15 text extensions. `config.TEXT_EXTENSIONS` actually contains 30, adding: `.toml, .ini, .cfg, .sh, .bash, .zsh, .go, .rb, .rs, .c, .h, .cpp, .hpp, .cs, .kt, .swift`.

## 8. Skip rules incomplete — **missing**

Spec mentions only `.DS_Store, .gitignore, *.lock, node_modules/**`. Real configuration in `config.py`:

- `SKIP_NAMES`: adds `.gitkeep`
- `SKIP_SUFFIXES`: `.lock, .pyc`
- `SKIP_DIRS`: `node_modules, .git, __pycache__, .ingest, .venv, venv, .tox, dist, build, .mypy_cache`

## 9. Step 2 ordering claim wrong — **drift**

Spec says Step 2 is "Processed bottom-up: deepest directory level first." In code, `run_summarize_step` iterates the manifest records in insertion order — there is no bottom-up traversal at Step 2. Only Step 3 (reduce) is bottom-up.

## 10. Resume-prompt UX promised but not implemented — **breaking**

Spec § "Resumability" promises:

```
Existing ingest state detected (step {N}/4). Resume? [y/N/amend]
```

with branches `y` (resume), `N` (abort), `amend` (delegate to `ingest-amend`).

Real `ui.confirm_resume()` is a plain `click.confirm()` with **default=True** — no third option, default is "y" not "N", and there is no escape into amend mode. Users following the spec to amend interactively will not find that path.

## 11. `state.json` schema missing fields — **drift**

Spec schema lacks `max_binary_mb` (int) and `locale` (str) which are present on the real `State` dataclass and serialized on every save.

## 12. Step 1 chunking thresholds inconsistent — **drift**

Spec § "Step 1" says text files chunk at **500,000 bytes** and PDFs chunk at **200 KB**. Code uses `CHUNK_SIZE_BYTES = 200_000` for both via `_chunk_text()` in `extract.py` — the 500 KB text-file figure quoted in the spec doesn't match the binary. (The 500 KB figure does appear in the agent-orchestrated `.claude/commands/ingest.md` template, which is a separate code path.)

## 13. Stray empty code block — cosmetic

Lines 165-166 of `spec.md` contain an empty ```json fence with no content. Likely an editing artefact.

## 14. Spec omits `ingest-add` duplicate-skip warning — **drift**

Spec describes duplicate handling in `ingest-add` but doesn't mention that each duplicate produces a yellow `Warning:` line via `print_warning`. Minor but user-facing.

## 15. Manifest `status` values incomplete — **drift**

Spec lists `pending, completed, failed, skipped-oversized`. Code also uses `"extracted"` as an intermediate status set by the extract step before summarize runs. Code paths that filter `status in ("extracted", "pending")` would surprise a reader who only saw the spec.

---

## Risk summary

The four highest-impact gaps for users following the spec as documentation:

1. **CLI signatures (#1)** — every `ingest-add`/`ingest-amend` example in the spec is broken.
2. **Missing locale section (#2)** — a substantial subsystem is undocumented; users won't know `--locale` exists.
3. **Wrong prompt contracts (#4, #5, #6)** — anyone editing `prompts/*.txt` based on the spec will produce output the parsers can't read (tags must live under `## Key Topics`).
4. **Resume UX mismatch (#10)** — users will hit a yes/no prompt where they expected three options.

`spec.md` is being updated in the same change as this audit; this file is the historical record of what was wrong at the time of review.
